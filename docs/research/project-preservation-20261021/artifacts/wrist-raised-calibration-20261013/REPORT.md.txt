## Найденная ошибка

Старая controller calibration регистрировала Qoffset=inverse(B*C0)*Wphysical0. При A с поднятыми руками и стоящим роботом вниз направленная кисть робота становилась целью при текущей ориентации контроллера. Для трёх raised калибровок разница между этой физической кистью и нейтральной анатомической кистью вдоль исходного предплечья: слева97.6–107.8°,справа80.5–91.9°. В down калибровке разница меньше справа23.6°,но слева76.95°: сохраняется и несовпадение осей. Исходный физический wrist-forward STAGE y=-.913, source-neutral y≈0..+.285 для raised cases.

Это дефект привязки, а не необходимость для оператора повторять стартовую позу робота. Прежний эксперимент meta_retarget_segments.cpp подгонял длины и положения14 целей, сохраняя их ориентации; эта ошибка им не исправляется автоматически. Полный скелет полезен для дальнейшего моделирования анатомии плеч/корпуса, но84 независимых IK задачи не являются проверенным решением для G1 с29 суставами. К этому исправлению новые задачи не добавлены.

## Исправление

Новая controller_anatomical_frame: Wneutral0=B*Fsource0*Fbind_offset*Wrest_G1. Qoffset=inverse(B*C0)*Wneutral0. F — исходное предплечье Meta, Wrest — нейтральный forearm→hand из bindFK робота. Подъём руки вращает Fsource0 и C0 совместно, поэтому их взаимная поправка сохраняется. Текущая физическая поза кисти больше не используется как нейтраль. Дальнейшие движения/повороты кисти идут от контроллера; GMR решает настоящую цепочку и joint limits, нет фиксации/телепортации/перезаписи wristqpos.

Новое поле true в live runtime и66 metadata вариантах, включая все политики/сцены. Legacy recordings без поля сохраняют старую калибровку. Заодно исправлен обнаруженный пропуск controller_stage_targets в whitelist manifest reader: ранее поле было записано и читалось функцией, но JSON collector его не сохранял. Новые явные true/false/missing/nested/duplicate/type regression tests исключают эту ошибку. Это ошибка офлайн replay, не причина живой калибровки.

Soft grip cup/rubik,menu/loading protection,SONIC backpressure,EGL generation fixes сохранены. Политики не переобучены и не менялись.

## Уточнение: предсказанные Quest кисти

Пользователь уточнил, что речь о кистях, предсказанных самим Quest, которые в полном скелете визуально совпадали с реальным положением контроллеров. Первоначальное утверждение «полный скелет не решит» было слишком категоричным. Ограниченный вывод: одна подгонка длин сегментов или увеличение числа IK constraints не устраняет доказанный physical-wrist calibration offset. Прямое использование анатомической ориентации предсказанной кисти/ладони может устранить потерю дополнительной артикуляции, которую forearm-neutral регистрация обнуляет в момент A.

В full-palm-controller-comparison.json по всем4 эпизодам измерено изменение относительного frame controller→Meta palm от калибровки. Median слева2.0/2.3/2.3/4.0°,справа1.9/1.3/2.9/6.8°; controller→forearm median слева17.6/14.2/24.5/47.1°,справа24.6/1.35/21.7/41.9°. Это различная артикуляция и стабильность относительного frame, не абсолютная ошибка SDK и не groundtruth человеческой кисти. Palm/grip расстояния≈5.7–8.2см относятся к различным физическим точкам; их нельзя назвать ошибкой совмещения ладони.

Это аргумент в пользу анатомической регистрации контроллера по предсказанной кисти/ладони и её bind-frame, вместо только нейтрали предплечья. SDK wrist и forearm уже присутствуют в выбранных14; дополнительные palm/fingers находятся в raw84. Нельзя обещать, что автоматически добавленные84 задачи IK всё исправят. Сравнение такого wrist/palm варианта с установленной forearm-neutral версией ещё не выполнено; новый APK на этом уточнении не собран/не установлен. Установленный ffeea973... по-прежнему forearm-neutral, новая живая приёмка отсутствует.
