# Очередь GPU для clearance V2

**Статус на 12 октября 2026, 11:39:19 UTC:** R1 smoke завершён успешно
в 11:32:05 UTC: 4096 сред, два critic updates, один actor update и все
контракты пройдены. Все четыре обучения активны: control seeds 11/22 на
GPU 0/3, clearance seeds 11/22 на GPU 2/4. У всех идёт critic warmup,
actor updates = 0. Это старт матрицы, не результат качества; [срез](../EXECUTION_STATUS.json).

Первая попытка control seed 22 завершилась в 11:32:54 UTC с PhysX CUDA
illegal memory access при создании среды, до config/metrics и optimizer.
Её output и пять файлов состояния сохранены с проверкой SHA256. После
проверки отсутствия её процессов выполнен один ручной повтор с тем же
seed/кодом на свободной GPU 3. Остальные работающие задания не прерывались;
clearance seed 22 впервые запущен на GPU 4. Очередь возобновлена в
11:38:30 UTC. Причина сбоя не локализована до аппаратуры GPU 1.

Первоначальная очередь остановилась после smoke exit 1 в 11:18:35 UTC:
начальная FK-проверка сравнивала буферы разных моментов. R1 синхронизирует
буферы без шага физики, сохраняя исходный допуск и reward. Старые failed state
и логи сохранены; R1 использует отдельные каталоги source/state.

[Оркестратор](run_queue.py) запускает задания по мере освобождения GPU,
не более четырёх одновременно. Сначала выполняется smoke на 4096 средах.
До матрицы control/clearance × seeds 11/22 проверяются exit 0, один actor
update, геометрический GPU-контракт, исходная конфигурация PPO, critic 1743
и завершённая baseline из 24 прогонов с совпадающим fingerprint.
Замороженные trainer и evaluator не изменены.

Успех каждого обучения требует 1000 actor updates, terminal phase `complete`,
`final.pt` и результатов оценки всех четырёх checkpoints 250/500/750/1000.
Сам по себе exit 0, включая `critic_not_ready`, успехом не считается.
Это проверка завершения эксперимента; принятие кандидата определяется
отдельной оценкой, описанной [в постановке V2](../README.md).

GPU допускается только при памяти менее 100 MiB, загрузке 0% и отсутствии
compute-процессов. Активные задания удерживают назначенную GPU до выхода
собственного trainer. Проверки не обеспечивают атомарную резервацию против
внешних процессов. Если GPU занялась до старта дочернего процесса, попытка
откладывается и архивируется только после явного доказательства отсутствия
запущенного обучения. Неоднозначный запуск блокирует новые задания.

Чужие процессы не завершаются. Файл `STOP` в каталоге состояния останавливает
только новые запуски; активные обучения продолжают работу. Повторный запуск
проверяет собственные argv, время рождения процессов и сохранённые хэши.
Хэши всех обучающих файлов проверяются при старте очереди и перед запуском
задания, а не на каждом ожидании занятой GPU.

## Запуск и проверка

[Публичный пример параметров](public-config-example.json) использует placeholders
и GPU 0–7 при максимуме четырёх активных заданий. Внешние зависимости и
раскладка входов описаны в [EXPERIMENT.json](../EXPERIMENT.json).

```sh
python run_queue.py run --root "$TRAINING_ROOT" --code "$FROZEN_V2_SOURCE" --state "$QUEUE_STATE" --gpus 0 1 2 3 4 5 6 7 --poll 15
PYTHONDONTWRITEBYTECODE=1 python test_run_queue.py
PYTHONDONTWRITEBYTECODE=1 python independent_queue_review.py
```

Локально прошли [22 основных теста](cpu-tests.json) и
[10 независимых тестов](independent-review-tests.json). Они проверяют
оркестрацию с mock-процессами и не запускают обучение или GPU.

Код, тесты, receipts и [исходный манифест R1](source-manifest.json)
скопированы побайтно. Единственное изменение кода очереди относительно
первой версии — SHA256 нового манифеста trainer. Старые failed state,
логи и исходники сохраняются отдельно; R1 использует новый каталог
состояния. [Манифест публикации](PUBLICATION.json) фиксирует состав копии.
Автоматического деплоя нет.
