# Новые записи чашки: HOMIE-v2, 15 октября 2026

Новая сессия оператора в симуляции FURRY на Meta Quest 3: **59 успешных
демонстраций**, 533,74 с движений до первого успеха, 16 042 RGB-кадра на сетке
30 Гц. Запрошенный набор «60 записей» фактически содержит 59 успешных эпизодов:
это подтверждено списком экспорта и повторным чтением метаданных Quest.
В этой сессии также были 13 попыток с outcome=0; они не входят в этот
подготовленный набор. Ничего не дополнено дубликатами.

Это отдельная сессия HOMIE-v2 с `catch_up=true`, а не прежние записи
[HOMIE Standing](../2026-10-15/README.md). Исходная политика и модель сохранены
в каждом эпизоде. Все 1180 исходных файлов проверены по независимым SHA256,
полученным с Quest при копировании. Служебные `.download-exported` не включены.

## Состав и ограничения

- `raw/`: 59 эпизодов с физическими состояниями, командами, камерой,
  моделью MuJoCo и ONNX; исходные файлы сохранены побайтно.
- `rendered/cup59-no-shadow-causal.hdf5.part*`: 90 частей готового HDF5;
  после сборки — RGB 224×224, действия
  float32 `[N,39]`, предыдущая команда, индексы исходных кадров и время.
- `manifest.json`: размеры и SHA256 всех исходных файлов и HDF5.
- `training-manifest.json`: соответствие demo → episode и состав split.
- `quality-audit.json`: результаты отбора, наклоны чашки/робота и длительности.

Все 59 демонстраций находятся в `mask/train`; `mask/valid` пуст.
Разделение сохранено из уже использованного экспорта. Отдельные случайные
сцены для проверки политики не являются held-out демонстрациями.
Это одна сессия, не независимый тест обобщения.

RGB — офлайн-рендер сохранённой симуляции, **не экран Quest, passthrough
или внешняя RGB-D камера**. Физическая поза берётся из текущего отсчёта,
поворот взгляда — из предыдущего отсчёта 30 Гц; в первом кадре используется
сохранённый начальный взгляд. Тени отключены, 640×360 масштабируется до
224×224 bilinear. Первая предыдущая команда нулевая, остальные точно равны
действию предыдущего отсчёта. Действие: 35 body-reference + 2 Grip + 2 gaze.

Сетка RGB/действий 30 Гц не совпадает с нативными тиками HOMIE 50 Гц.
Записи не гарантируют полный префикс от reset; этот экспорт не добавляет
отсутствующее начало и не исправляет контракт частот. Наличие успешных
демонстраций не означает, что обученная политика успешно работает с нуля.
Полный формат и принципы рендера описаны в
[документации первой публикации](../2026-10-15/README.md).

## Скачать и проверить

Из корня FURRY, с Git LFS и Python 3.12:

```sh
git lfs install
git lfs pull --include='datasets/quest-cup/2026-10-15-homie-v2/**' --exclude=''
python3.12 -m venv .venv
.venv/bin/python -m pip install -r datasets/quest-cup/2026-10-15-homie-v2/tools/requirements.txt
.venv/bin/python datasets/quest-cup/2026-10-15-homie-v2/tools/camera_data.py verify
```

HDF5 хранится 90 частями по 8 МиБ (последняя короче) для параллельной передачи.
`verify` и `video` автоматически собирают исходный HDF5 и проверяют его SHA256.
Нужно дополнительно около 0,75 ГБ места. Части сохраняются для повторной
проверки. Собранный файл побайтно совпадает с исходным экспортом.

Проверка читает все RGB и сверяет SHA256, команды, предыдущие команды,
индексы и время с исходными записями. Архивным MJB нужна MuJoCo 3.3.7.
SHA256 готового HDF5:
`05376522259b4eb9091a80d41a31b0a768b3933349a231d69de5580fdb32b9cd`.

## Видео и повторный экспорт

Готовое RGB-видео первого эпизода (нужен ffmpeg):

```sh
.venv/bin/python datasets/quest-cup/2026-10-15-homie-v2/tools/camera_data.py video \
  episode-1792058834151648 /tmp/cup-homie-training.mp4
```

Добавьте `--recorded-gaze` для восстановления сохранённого вида камеры
640×360 вместо обучающих RGB. MuJoCo выполняет кинематику сохранённых поз,
политика не запускается. Для headless Linux требуется настроенный EGL
(`MUJOCO_GL=egl`); на macOS — графическая сессия.

Повторный экспорт одного эпизода с тем же причинным выбором взгляда:

```sh
.venv/bin/python datasets/quest-cup/2026-10-15-homie-v2/tools/camera_data.py rebuild \
  /tmp/cup-homie-one.hdf5 --episode episode-1792058834151648
```

Без `--episode` экспортируются все 59 демонстраций, 59 train / 0 valid.
Существующие выходные файлы не перезаписываются. Различные OpenGL-драйверы
могут давать небольшие различия пикселей; для одинакового окружения доступна
проверка `verify --render-check`.
