# NOTES.md — TWIST2 (arXiv 2511.02832v1) под цель «телеоп-данные для ретаргетинга»

Создан 05.10.2026 (сессия менторства, день 1 SHAD-интенсива). Источник: полный текст v1 через arXiv; локальный PDF + RU-перевод лежат рядом.

## Что это

TWIST2 (Ze et al., стажировка в Amazon FAR; Stanford/Berkeley) — портативная система телеоперации и сбора данных для гуманоида **без мокапа**: полный whole-body контроль + переносимость + один оператор. Unitree G1 29 DoF + Dex31.

**Пересечение с нашей линией:** ретаргетинг в TWIST2 = **GMR** (YanjieZe/GMR, Retargeting Matters 2510.02252) — тот же метод, что в SHAD-эксперименте (`../shad_interview/experiment/`) и декабрьской статье (`../retargeting_paper/`). Наша статья квантифицирует артефакты GMR оффлайн; TWIST2 — GMR в онлайн-петле телепа.

## Пайплайн (§III)

```text
PICO 4U VR (100 Гц, XRoboToolkit)          ~$1000, сетап ~1 мин, без калибровки
  шлем + 2 контроллера + 2 трекера на голенях (2-трекерный режим стабильнее большего)
  → GMR-ретаргетинг (адапт. под VR)        §III-D
  → p_cmd, 50 Гц (Redis)                    ф. (1)
  → π_low: RL motion tracker (PPO)          §III-E, 20к клипов
  → PD → крутящий момент                    ф. (4)
Сверху: π_high^auto = Diffusion Policy на собранных демо (§III-G)
Зрение: 2-DoF шея ($250, 2× Dynamixel XC330) + Zed Mini стерео на шее
```

### p_cmd — командный вектор (= будущее действие политики)

`[ẋ, ẏ, z_ref, φ, θ, ψ̇, q_ref]` — относительные скорости/углы корня + позы всех суставов.
Проприоцепция политики = история `p_cmd`, **не** сырые состояния `s` (декаплинг от π_low + устойчивость к шуму).

## Уроки «как правильно собирать телеоп-данные»

1. **Действие политики = командный вектор, не сырые суставы.** Оператор пишет ровно то, что потом предсказывает π_high. Данные ↔ интерфейс совпадают by design.
2. **Относительные координаты корня, не абсолютные** — не зависит от глобальной оценки позы (у VR шумная), устойчиво в длинных сессиях, переживает телепортацию оператора.
3. **Ретаргетинг под VR-шум (ф. 6):** низ — позиционные+ротационные констрейнты (меньше foot slide = наша метрика), верх — только ротационные; позиции в pelvis-фрейме. Стейдж-1 GMR (консистентность ротаций звеньев) без изменений.
4. **Руки как гриппер:** Dex31 ≈ параллельный гриппер; кнопки контроллеров → α∈[0,1], интерполяция q_open↔q_close (ф. 7); два пресета (power grasp / pinch). Никакого хэнд-ретаргетинга.
5. **Шея = качество данных:** аблейшн Table III (10 демо, novice/expert): full 68 c vs w/o Stereo 98 c vs w/o Neck 112 c. Без стерео хваты «выше цели», без шеи — слепые зоны. Эгоцентрия обязательна для мобильных задач.
6. **Domain gap ↔ устройство:** 73 клипа, записанных самим PICO, к 20к AMASS/OMOMO/TWIST-мокапу — достаточно для bridging.
7. **Запись непрерывная → нарезка потом:** GUI сегментирует длинные записи на эпизоды, режет idle-действия, удаляет фейлы.
8. **Один оператор = контроллеры как control center:** start/pause/end с джойстика; при unpause — интерполяция от последней позы робота к текущему таргету (без рывков). Пауза = усталость не портит датасет.
9. **Латентность < 0.1 c** (все модули >50 Гц), против 0.5 c у TWIST-1. Стерео в PICO: GStreamer h265, IPD-шейдер, фокус ~1 м.

## Лимиты (авторские, §V)

1. Трекинг не тянет высокодинамичные движения (спринт).
2. PICO-оценка позы хуже мокапа, особенно локти/колени — там нет трекеров → качество движения падает.

## Сессия 06.10.2026: GT с камеры RealSense D435i (аугментация + GT для регресса ретаргетинга)

**Полная документация пайплайна (архитектура, бенчмарк, грабли, план): `PIPELINE.md`**

**Сетап**: D435i, USB 3.2 (кабель USB2 был блокером — цвет вообще не стримит). Без NVIDIA GPU → CPU-only. Окружение: `.venv` (py3.12, MediaPipe-стек) + conda `nuitrack` (py3.10).

**Текущий бейзлайн** (`pose_realsense.py`): MediaPipe Pose Landmarker full (33 кт, BlazePose ~2020, MobileNetV2-подобный энкодер — устарел) + depth-фьюжн (медиана 7×7 px → deproject → метрический 3D) + EMA. Одно окно: цвет+скелет | 3D-скелет. Вывод ресерча v1: метрический 3D берём из глубины, не из нативного 3D модели (MediaPipe world-Z шумит 5-15 см).

**Nuitrack (v2026.1)** — разобран и выкинут (проприетарный, триал-ключ, 19 суставов). Внутри гибрид: TF-CNN детектор + CnnHPE (~3 МБ CNN по depth) + decision-trees bodyparts (наследие Shotton/Kinect) + skeleton_limits.xml (анатомия) + FABRIK IK + кинематический фильтр. **Что спереть**: анатомические лимиты + кинематический фильтр как пост-проход над нашим GT (референс-форматы в `%NUITRACK_HOME%`).

**PCT** «Human Pose as Compositional Tokens» (2303.11638, CVPR23; Gengzigang/PCT): поза → M дискретных токенов (VQ-кодбук, подс-структуры суставов), оценка = классификация токенов. Сила — окклюзии. Как детектор не годится (COCO-17, Swin+mmcv, мёртвый репо, GPU). **Ценность для нас**: (1) прайор/архитектура для самого регрессора HMD→тело (зависимости суставов на скудном входе — ровно наша задача), (2) заполнение окклюзий в офлайн-GT с флагом synthetic. Опасность: «правдоподобные галлюцинации» не должны молча попадать в GT.

**Открытый ресерч v2** (критерий: open-source пермиссивные, CPU, ONNX без сборки): RTMO/RTMW one-stage wholebody-133, DWPose/RTMPose, ViTPose+, ED-Pose, token-последователи PCT, 3D-lifting (MotionBERT/DiffPose/HMR2/WHAM) + гибрид: детектор → wholebody ONNX → depth-фьюжн → One-Euro + анатомические лимиты [+ token-completion окклюзий].
