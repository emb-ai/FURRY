# Денойзер v1: «шумный 3D → чистый 3D» (темпоральный)
### План · 11.10.2026 · данные: L2-запись от 10.10

---

## 1. Задача и отличие от v0

v0 (2D-кейпоинты → суставы) упёрся в два измеренных предела: 2D-вход не видит
сгиб колена к камере (на GT 40–60° предсказывал 12°), а метки 09.10 были без
амплитуды (p99 сгиба 46°). v1 меняет вход на **шумный depth-фьюжн скелет**
(сгиб виден: фьюжен ловил 141° против 44° у v0) и учится на L2-метках
с амплитудой (марш/приседы: теги читаются на 57°+).

Wire-контракт не меняется: выход = 6 суставов × xyz root-relative + conf,
врезка в pose_yolo (denoiser_ov) остаётся прежней.

## 2. Архитектура

```
ОКНО T=9 кадров (~0.3 c):
  фьюжн-скелет 17×(x,y,z,conf) root-relative, норм.   ← главный вход (depth)
  + 2D-кейпоинты 17×(u,v,conf)                        ← страховка при провалах
  + src-флаги (window/line/missing)
        │  per-frame MLP 85→256
        ▼
  темпоральный энкодер: causal-TCN ×2 (dilation 1,4) / GRU-256
        │
        ▼
  ГОЛОВЫ:
   1. прямая → 18 (x0_direct): бейзлайн + инициализатор
   2. диффузионная: x0-параметризация, FiLM от t, DDIM-5,
      старты obs / prev (как v0)
   3. conf-голова: per-joint log-σ, гетероскедастичный NLL
```

~3M параметров, CPU/OpenVINO 5–15 мс/кадр с окном.

Лосс: Huber(x̂₀, GT) + λ₁·NLL-conf + λ₂·bone-length (длины оператора) +
λ₃·velocity-consistency.

## 3. Данные

| Роль | Источник | Объём |
|---|---|---|
| Train | `l2_session2.db3` (600 с) | ~16.6k кадров |
| Val | `l2_session1.db3` (229 с, прерванный дубль: синк+статика+марш) | ~6k кадров |
| Пары | вход = фьюжн-скелет офлайн (fusion.py по багу, обход align §6.3) ↔ GT = теги (subpix) | один проход на дубль |

Датасет: `l2_dataset/` (отдельная папка): `l2_session*.npz` (t, 2D, фьюжн,
теги, seen), offsets json, потом `v1_pairs.npz`.

Аугментации входа: измеренный шум фьюжна (джиттер Z ±4–6 см, дропауты,
переключения src — распределение снимаем с той же пары вход↔GT).

## 4. Пайплайн работ

1. `l2_extract.py`: проход по багу → npz (YOLO-OV + теги-subpix + фьюжн). ~25 мин take2, ~6 мин take1.
2. Оффсеты тег→сустав: L1-Гаусс-Ньютон (как v0) на take2, применение к обоим.
3. `l2_build_v1.py`: пары (окно входа ↔ GT-18) + нормировка + split.
4. `train_denoiser_v1.py`: та же база, что v0 (FiLM-транк), вход-окно + conf-голова.
5. Eval: MPJPE + **сохранение амплитуды колена в блоках марш/присед**
   (главная метрика: GT 57°+ не должен сглаживаться в 40°).
6. Живой A/B на Quest (амплитудный протокол) через готовую врезку `--denoiser`.

## 5. Время

- Экстракция: ~30 мин оба дубля (CPU).
- Обучение v1 на CPU: ~1.5–2 ч при 300 эпохах (v0: 300 эпох × 9k сэмплов ≈ 15 мин;
  v1: ×1.8 данных, ×2–2.5 вычислительной цены окна/TCN, +conf-голова).
- Оценка: минуты.

## 6. Результаты v1.0 (11.10, 300 эпох CPU ~24 мин)

| метрика (val 583) | сырой фьюжн | v1 прямая | v1 obs/10 |
|---|---|---|---|
| MPJPE, см | 7.87 | **6.15** | 6.24 |
| std костей, см | 3.53 | 1.23 | **0.91** |
| джиттер, см/кадр | 1.44 | 1.04 | **0.92** |

Амплитуда колена ВСЁ ЕЩЁ сминается (GT 60–75° → предикт 19–32°). Диагностика
показала корень — **не вход, а метки**: сгибов >60° в сырых тегах 9–15% кадров,
но после eligibility+костяного гейта в парах остаётся **0.6%** (29 кадров):
на глубоком сгибе стопные пластины гуляют (оффсет лодыжек |r| p90 100+ px),
лодыжка GT умирает → гейт косит кадр. Плюс time-split val попал в хвост
без амплитуды (5+1 кадров >60°).

Вывод: v1 готов как «чистильщик позиций» (drop-in на шов), амплитуда требует
меток — следующий шаг v1.1: боковая камера для лодыжек на сгибах (запись уже
есть: side_181700.avi), либо жёстче стопы при следующей съёмке, либо
класс-взвешенный лосс как паллиатив.

## 7. Известные риски

- Фьюжн-вход на глубоких приседах сам теряет суставы (depth-дыры) — окно +
  src-флаги должны держать; если нет — усилить вес 2D-ветки.
- GT на пиках приседа: теги бедра при крутом наклоне читаются хуже (замерено
  57° в одиночном кадре — посмотрим по всему дублю).
- Один оператор/камера — как у v0; генерализация не заявляется.
