# AGENT.md — инструкции: камера → скелетон → передача координат на шлем

Для агента/человека, который этого проекта не видел. Читать сначала
`PIPELINE.md` (архитектура, бенчмарки, грабли §6). Репозиторий команды:
**emb-ai/FURRY** (`main/skeleton/` — этот пайплайн; `prototypes/quest_g1` —
приложение шлема; `docs/Architecture-and-Decisions.md` — ADR-002 транспорт,
ADR-006 RGB-D fusion; наша работа = evidence к ним).

Роль системы: внешняя D435i смотрит на оператора в VR и даёт **метрический
3D-скелет** (главное — ноги, которых у Quest-трекинга нет). Живой поток идёт
на шлем для аугментации ног; одновременно тот же поток = GT-датасет.

## 1. Установка софта камеры

### 1.1 Windows (основная конфигурация, всё уже работает — проверять)

```powershell
cd C:\Users\denis\ml\self_assistant\sirius_twist
.venv\Scripts\python -m pip install -r requirements.txt --default-timeout=120 --retries=5
.venv\Scripts\python realsense_test.py        # линк должен быть USB 3.x!
.venv\Scripts\python pose_yolo.py             # см. §2
```

- Кабель **обязательно USB 3.x** («зарядные» дают линк 2.1 → цвет не стримит,
  симптомы в PIPELINE.md §6.1).
- Перед запуском закрыть RealSense Viewer и другие превью — держат камеру.
- Веса: `models/yolo11s-pose.pt`. Бекенды: `yolo11s-pose.onnx`,
  `yolo11s-pose_openvino_model/` (уже экспортированы). Если OV-папки нет:
  `.venv\Scripts\yolo export model=models/yolo11s-pose.pt format=openvino`.
- **Не ставить** torch и OpenVINO бенчить в одном процессе — душат друг друга
  (§6.10), каждый бекенд в своём процессе (`bench_onnx.py`).

### 1.2 macOS / M4 (необязательная вторая конфигурация)

Колёс `pyrealsense2` под macOS на PyPI **нет** — только сборка из исходников.
Ограничения macOS-бэкенда: Viewer не работает, **IMU отключён**, на macOS 12+
USB-инструментам нужен sudo. Подробнее: PIPELINE.md, раздел macOS.

```bash
xcode-select --install
brew install cmake libusb pkg-config openssl librealsense
git clone https://github.com/IntelRealSense/librealsense.git && cd librealsense
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release -DBUILD_PYTHON_BINDINGS=true \
         -DPYTHON_EXECUTABLE=$(which python3.12)
make -j4 && sudo make install

# проект:
cd <проект>
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt   # pyrealsense2 не ставится — он из сборки выше
.venv/bin/python -m pip install coremltools
.venv/bin/yolo export model=models/yolo11s-pose.pt format=coreml   # CoreML-бекенд
.venv/bin/python bench_onnx.py 200 all                 # mps + coreml против оценок
sudo .venv/bin/python realsense_test.py                # sudo из-за USB на macOS 12+
```

Инференс на M4 (оценки): torch-MPS 15–25 мс, CoreML-GPU 8–15 мс, CoreML-ANE
4–8 мс. Захват на маке после сборки — проверить `realsense_test.py`; если
нестабильно — вернуться к Win-конфигурации, это нормально.

## 2. Поднять скелетон (live)

```powershell
.venv\Scripts\python pose_yolo.py            # OpenVINO + spatial-фильтр (default: min)
.venv\Scripts\python pose_yolo.py s off      # без depth-фильтров — максимум fps
.venv\Scripts\python pose_yolo.py s full     # максимум качества (temporal+holes)
```

Проверка здоровья (консоль раз в секунду печатает `[тайминг]`):

| Стадия | Норма | Если хуже |
|---|---|---|
| infer | 36–45 мс (OV) | увидел `torch-cpu` в первой строке → нет OV-папки |
| filters | 0 (off) / ~18 (min) / ~45 (full) | машина фонит (Defender) |
| show | ~7 мс | вернулись полноразмерные панели |
| align | ~12 мс | следующий резерв оптимизации |
| fps | 12–16 (off) / ~12 (min) | смотреть сумму стадий выше |

Окно: слева цвет+2D-скелет, справа 3D (метры, таз=0). `q`/Esc — выход,
стрелки — вращение 3D. Человек в 2.5–3 м, целиком в кадре (стопы видны!).

## 3. Передача координат на шлем (контракт — делать ровно так)

### 3.1 Транспорт и направление

- **WebSocket**, изолированный роутер LAN, сервер на ПК: `ws://0.0.0.0:8765`.
- Python: пакет `websockets`, **sync-сервер** (`websockets.sync.server`) в
  отдельном потоке + потокобезопасная очередь — main-петля OpenCV остаётся
  синхронной. Никаких asyncio-костылей в главном цикле.
- **Двунаправленно**: шлем шлёт вниз свои позы (нужны для калибровки и пар),
  ПК шлёт вверх скелет.

### 3.2 Downlink: ПК → шлем (скелет)

JSON, **на каждый обработанный кадр** (12–16 Гц), даже пустой (heartbeat):

```json
{
  "t": 1728300000123,          // host epoch мс НА МОМЕНТ КАДРА (не отправки!)
  "seq": 412,
  "fps": 14.2,
  "backend": "openvino",
  "frame": "pelvis-relative",  // суставы относительны тазу, метры, оси VR-мира
  "pelvis": {"p": [0.1, -0.9, 0.3], "conf": 0.98},   // таз в мире VR
  "joints": {
    "lhip":  {"p": [0.09, -0.05, 0.01], "conf": 0.9, "src": "window"},
    "lknee": {"p": [0.08, -0.38, 0.02], "conf": 0.7, "src": "line"},
    "lankle":{"p": [0.00, 0.00, 0.00],  "conf": 0.0, "src": "missing"},
    "rhip": ..., "rknee": ..., "rankle": ...,
    "nose": ..., "lshoulder": ..., "rshoulder": ...
  }
}
```

Правила:

- **Только низ + нос/плечи. Руки НЕ передавать** — оптический трекинг кистей
  на шлеме лучше нашего (и это фикс-паттерн TWIST2: верх — ротации от VR).
  Полный набор: `pelvis, lhip, lknee, lankle, rhip, rknee, rankle, nose,
  lshoulder, rshoulder` (+ стопы, когда перейдём на RTMW-133).
- `src` — провенанс: `window` (гейт-медиана) | `line` (достройка вдоль кости)
  | `missing`. Пропавший сустав шлём с `conf: 0`, НЕ замалчиваем.
- Диагностика времени (необязательные поля, приёмник может игнорировать):
  `clock` — источник `t` (`global_time` | `system_time` — время снимка;
  `host_after_wait` — часы ПК после `wait_for_frames`, `t` позже снимка),
  `frame_age_ms` — возраст кадра к выходу из ожидания, `dropped` — сколько
  накопившихся старых кадров выброшено ради самого свежего.
- Единицы метры; после калибровки (§3.4) — оси VR-мира, y вверх. До
  калибровки можно слать в осях камеры (x вправо, y вниз, z вперёд) с
  `"frame": "camera"` — приёмник обязан проверять поле `frame`.
- Никакой интерполяции/сглаживания на отправителе кроме One-Euro уже в
  пайплайне: сглаживание/предикция — на приёмнике, где знают частоту рендера.

### 3.3 Uplink: шлем → ПК (позы для калибровки и пар)

JSON, максимальная доступная частота (72–100 Гц):

```json
{
  "t": 1728300000456,        // epoch мс по часам ОТПРАВИТЕЛЯ
  "hmd":   {"p": [..3], "q": [w,x,y,z]},
  "ctrl_l": {"p": [..], "q": [..], "tracked": true},
  "ctrl_r": {...}
}
```

- Таймстамп источника, **не** время прихода пакета (WiFi-джиттер).
- Эти же позы пишем в лог — они же вход будущего регрессора.

### 3.4 Калибровка камера↔VR (обязательна, раз за сессию)

Камера стоит на месте. Один AprilTag 36h11 известного размера виден в углу кадра:
на печати сторона чёрного квадрата равна `--marker-m`, вокруг нужна белая
бумага. `marker_frame.py`, порядок действий — `MARKER.md`.

1. **Время**: ПК и шлем в одном host-клоке (epoch мс); остаточный сдвиг —
   ping/pong по минимальному RTT. Контроль — фаза SYNC (3 приседа-прыжка).
2. **Пространство**: solvePnP по цветному кадру даёт позу маркера в осях
   камеры, без глубины. Поза того же маркера в STAGE — поза контроллера в
   момент касания (`c` в превью, рука `--marker-hand`, нужен `--ws`):
   точка uplink в центре наклейки, контроллер смотрит в плоскость, его верх
   совпадает с верхом маркера. Масштаб 1. `p_stage = R @ p_camera + t`.
   Печать: `python marker_frame.py --write marker.png --marker-m 0.16`.
3. Фиксация только по устойчивому маркеру (≥5 кадров за 0.5 с, репроекция
   < 2 px, разброс < 15 мм и 2°, сторона в кадре ≥ 40 px) и свежей позе
   контроллера (< 150 мс, `tracked`). Результат — в `--session` / `session.json`.
   Пока связка не зафиксирована, downlink остаётся `frame=camera`.
4. После фиксации downlink — `frame=pelvis-relative`: суставы относительно
   таза уже в осях STAGE, `pelvis.p` абсолютный. Приёмник эту связку второй
   раз не считает. Сырьё в осях камеры пишется в лог с `direction=camera`.

### 3.5 Приёмник на шлеме

- Слияние: локальный скелет (72 Гц, плавный, ноги врут) — скорость; камера
  (12–16 Гц, латентная, метрически честная) — коррекция смещения. Экстраполяция
  constant-velocity до частоты рендера.
- **Bounded hold**: пропуск > 150 мс — держим последнее с интерполяцией и
  видимым флагом STALE; > 500 мс — деградация до локального скелета целиком.
  Вечный повтор последнего пакета запрещён (требование FURRY ADR-002).
- Быстрейший путь посмотреть без правки APK: **страница HTML в браузере Quest**
  (`ws://<ip-ПК>:8765`, WebXR даёт позы для uplink, canvas/three.js рисует
  скелет). Нативный мерджер в `quest_g1` — после успешной визуальной оценки:
  точки+conf в pelvis-фрейме перед `MetaRetargeter`.

### 3.6 Замеры и приёмка

| Метрика | Порог |
|---|---|
| echo WS ПК↔шлем (1 мин) | медиана < 5 мс, p95 < 20 мс, без потерь |
| возраст скелета на шлеме (t→рендер) | медиана < 100 мс |
| репроекция маркера при фиксации | медиана < 2 px, разброс позы < 15 мм и 2° |
| дропаут суставов ног (лицом к камере) | < 10% кадров |
| hold с видимым STALE-флагом | все случаи > 150 мс |

## 5. Чем НЕ заниматься

- Не передавать руки/пальцы — они с шлема.
- Не слать сырые глобальные координаты камеры без `"frame"` и калибровки.
- Не сглаживать на отправителе «для красоты» — только conf/провенанс.
- Не доверять времени прихода пакетов.
- Не запускать torch и OpenVINO в одном процессе (§6.10).
- Не держать RealSense Viewer открытым параллельно со скриптами.
