# Сбор демонстраций задач для обучения

Сборка сохраняет полные попытки задачи: реальные команды оператора, состояния
робота и предметов, исходные ONNX, скомпилированную модель MuJoCo, положение
камеры и автоматический исход задачи. После копирования на Mac из них
восстанавливаются RGB-наблюдения и формируется HDF5 для imitation learning.
Это картинки симулятора, а не видеозапись экрана Quest или внешней камеры.

## В очках

1. Выберите «Траектории», нужную сцену и вид от первого лица. Зафиксируйте одну
   политику для серии. Для задач стоя можно выбрать HOMIE Standing; не меняйте
   политику внутри серии, которую планируете обучать вместе.
2. Сбросьте сцену, откалибруйтесь. Нажмите Y **до первого касания предмета**.
3. Выполните задачу полностью. В cup — поднять чашку и отпустить на круге;
   в wb_dex — перенести чашку с полки в коробку на полу; в bimanual — разложить
   оба предмета нужными руками; в basket — перенести корзину через дверь на полку.
   Дождитесь «Готово», затем Y для сохранения. В push_t нужно совместить T с целью.
4. Сбросьте сцену и повторите с новым расположением. Записывайте и неудачные
   попытки: экспорт сохранит исходники, но исключит их из successful-only BC.

Одна запись — одна полная задача. Не делайте reset, повторную калибровку,
переключение вида или паузу посреди попытки. При потере трекинга закончите попытку
и начните новую. Меню после окончания записи допустимо. Режим записи только
скелета человека — другой датасет и сюда не экспортируется.

Автоматическая приёмка реализована для cup, wb_dex, bimanual, basket и push_t.
В остальных сценах сырые данные сохраняются, но exporter не выдаёт их за
успешные демонстрации без соответствующего проверенного критерия. У push_t
критерий — покрытие целевой T не менее 50%; это текущий критерий FURRY,
а не утверждение о полном совпадении с оценкой авторов.

## Копирование и экспорт

В корне этой копии проекта, с установленными requirements-learning.txt:

```sh
python scripts/pull_task_episodes.py outputs/task-recordings
python -m g1_sim.visual_dataset outputs/task-recordings outputs/cup.hdf5
```

Первая команда копирует только завершённые новые записи, проверяет каждый файл
по SHA256 на очках и не удаляет исходники. Альтернатива — скопировать ZIP из
Download/G1Quest и передать папку ZIP второй команде. Старые записи без
learning.json/learning-model.mjb не экспортируются молча с угаданной камерой.

Один HDF5 содержит одну сцену, модель и конфигурацию политики. Если в папке
разные конфигурации, exporter принимает первую и перечисляет несовместимые
в `<output>.report.json`; для остальных используйте отдельные папки/датасеты.
Существующий HDF5 не перезаписывается. Все отказы перечислены в отчёте.

На Mac нужен доступ к графической сессии для офлайн MuJoCo/OpenGL; на GPU Linux
можно установить MUJOCO_GL=egl. Версия MuJoCo должна совпадать с learning.json
(в этой сборке 3.3.7). В проекте этой поставки готовое окружение находится
в ../train-env: вместо python используйте ../train-env/bin/python.

## Формат

- HDF5: data/demo_N/obs/agentview_image — uint8 N×224×224×3, из RGB 640×360.
- data/demo_N/actions — float32 N×39: 35 компонент реально применённой
  whole-body reference, левый/правый grip, виртуальные yaw/pitch камеры.
- obs/previous_command — предыдущая команда на сетке 30 Гц; первая — нулевая
  стартовая метка. Будущие команды в observation не подмешиваются.
- timestamps, source_sim_time, source_frame_index сохраняют точную привязку.
  Выбор исходного кадра причинный: последний не позже времени сетки 30 Гц.
- Камера расположена в ego-точке робота и поворачивается по направлению взгляда
  HMD (без roll). Эти виртуальные yaw/pitch входят в action, чтобы направление
  камеры можно было воспроизвести при автономном исполнении. Это не физические
  суставы шеи G1 и не точная копия свободного положения головы пользователя.
- mask/train и mask/valid разделяют целые эпизоды; одинаковое содержимое
  исключается. По умолчанию 10% эпизодов в validation, минимум один при N≥2.
  Для одной записи validation пуст; независимую тестовую сессию это не заменяет.
- Кадры после первого успеха обрезаются. Начальные служебные снимки калибровки
  исключаются; внутренние разрывы и паузы отклоняют попытку. Дополнительные
  остановки оператора внутри корректной задачи автоматически не вырезаются.

Поддерживается generic HDF5-структура robomimic, но FURRY не является штатной
средой robomimic: для готового чужого trainer требуется адаптер 39-мерных actions
и этих observation keys. В репозитории есть работающий загрузчик VisualSequences
с окнами 2 observation / 64 action, padding и маской конца эпизода.

## Проверка обучения / локальный baseline

```sh
python -m g1_sim.visual_training outputs/cup.hdf5 outputs/cup-smoke.pt --steps 2 --batch-size 2
```

Это реальный forward/backward и обновление весов на RGB+командах. Для длинного
запуска можно увеличить --steps и выбрать --device cuda на машине обучения.
Реализация — **локальный baseline FURRY**, а не точная копия learner TWIST2:
ResNet18 обучается с нуля, R3M не подключён, denoiser из существующего FURRY.
Датасет не привязан к этому baseline. При оценке визуальной политики нужны та же
камера и рендер MuJoCo: штатные Quest GLES-шейдеры дают другую картинку;
перенос визуальной политики в автономный Quest пока не реализован.
Экспорт, два тестовых шага и сохранённый
checkpoint не доказывают решение задачи; автоматического deployment нет.

Контрольные записи tests/check_learning_capture.cpp помечены fixture=true;
обычный экспорт отвергает их. Они проверяют формат и не являются человеческими
демонстрациями. Сборку и подход к данным следует проверять первым коротким
живым успешным эпизодом до массового сбора.
