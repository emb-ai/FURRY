# Native GMR and Meta full-body input

Status (2026-10-06): implemented and tested on macOS; Android APK builds.
Quest installation and human tracking validation are pending USB authorization.
This replaces the production wrist-only IK path described in
[the historical tracking audit](TRACKING_AUDIT.md).

## What is ported

The C++ `GmrRetargeter` ports the two-stage GMR task stack, SE(3) residual and
Jacobian from Mink, task costs, Levenberg–Marquardt damping, iteration stopping
rule and joint configuration limits. MuJoCo's box-QP solver replaces DAQP;
for this free-root + 29-hinge model the configuration constraints are box bounds.
The original GMR G1 kinematic model is exported without visual assets. Body
frames, inertias, joints and limits remain available to the solver.

Sources:

- [GMR](https://github.com/YanjieZe/GMR/tree/bb1bbe40774794fceb2a7c579a3464a28e68c844),
  pinned at `bb1bbe40774794fceb2a7c579a3464a28e68c844`, MIT.
- [Mink 0.0.13](https://github.com/kevinzakka/mink), Apache-2.0; Lie algebra
  operations are adapted into native code. Licenses ship in the APK.
- [TWIST2](https://github.com/amazon-far/TWIST2/tree/b06178f19a22f2138cbd31f60c6d494bc263f67d),
  pinned at `b06178f19a22f2138cbd31f60c6d494bc263f67d`.

GMR is an optimization-based retargeter, not a learned human-to-robot policy.
Changing human height therefore does not create a learned-model OOD problem
inside GMR. Incorrect source axes/proportions can still produce bad targets;
the downstream learned TWIST2 policy can receive motions outside its training
coverage. The tests below do not establish that coverage.

## Quest-specific source adapter

Runtime pipeline:

```text
Meta OpenXR full-body skeleton + HMD
  -> bind-skeleton axes/proportion calibration
  -> native GMR (14 body tasks, full floating-base G1)
  -> 35-value whole-body reference
  -> original TWIST2 ONNX policy and motor gains
  -> MuJoCo physics
```

This is a new **Meta source adapter**, not the PICO/XRoboToolkit input stack.
`XR_FB_body_tracking` and `XR_META_body_tracking_full_body` supply 84 runtime
joints; 14 are selected by their documented IDs. The manifest declares
`com.oculus.permission.BODY_TRACKING`. Bind poses are matched by joint ID,
not array ordering. Runtime validity, confidence, time and skeleton revision
are checked. No body data means no teleoperation; there is no wrist-IK fallback.

At A-calibration, Meta's anatomical bind skeleton is aligned with a robot T pose.
Bone orientation offsets come from this bind pose, not from assuming that
controller, PICO and Meta bone axes match. Arm reach and pelvis height derive
scale factors from measured skeleton proportions. There is no fixed 0.8 hand
multiplier and no requirement to pretend the operator is 130 cm tall.
The original xrobot preprocessing remains in the solver for oracle comparison;
Meta targets enter the same task stack after their own source calibration.

Headset horizontal displacement from A-calibration sets root target translation,
scaled by the measured pelvis-height ratio. Pelvis height relative to the lower
estimated foot sets grounded root height. The runtime's legs are **estimated**,
not directly measured foot trackers. No analytic gait is generated by this app.
The target root velocity is differentiated at body sample timestamps and rotated
into the robot frame. TWIST2 receives velocity/height/orientation and 29 joint
angles, not an absolute XY position servo: exact position holding is not claimed.

Calibration/resume blends from achieved robot joints for 0.5 s. Invalid/stale
samples and pauses zero commanded planar/yaw velocity; the last joint target
remains. Body-proportion changes and OpenXR recenter invalidate calibration.
Tracking resumes after new A-calibration where required. Focus loss pauses
physics and resets reference-velocity history. X resets physics and calibration.

## Reproduced evidence

Run from the prototype root on this Mac:

```sh
.venv/bin/python -m pip install -r android/requirements-gmr-test.txt
./android/check_gmr_mac.sh
.venv/bin/python -m unittest discover -s tests -v
./android/build_apk.sh
```

- Unmodified pinned Python GMR + Mink/DAQP is the numerical oracle, not a second
  implementation of our C++ algorithm. 70 synthetic frames each at human heights
  1.30, 1.75 and 1.95 m, including root rotations up to 3.13 rad and joint limits.
  Maximum native/Python tangent-coordinate discrepancy: `1.075e-13`;
  acceptance tolerance `2e-4`. This isolates the native solver port.
- Meta adapter: three 100-frame synthetic trials vary source size, room yaw and
  local bone axes. Equivalent robot commands differ by at most `1.654e-14`;
  tolerance `1e-5`. Skeleton revision invalidation and resume velocities tested.
- Full native GMR -> TWIST2 -> MuJoCo: 1,000 frames / 10 simulated seconds of
  small shoulder motion, including a focus pause/resume, no fall. Minimum pelvis
  height 0.7813 m, final planar drift 0.0068 m on the desktop fixture. See the
  local log `outputs/gmr-meta-check.log` for runtime.
- Same recording is replayed from its raw skeleton and physical calibration
  state; all 1,000 accepted 35-value references match exactly on this Mac.
- Python tests check physical baseline and recording corruption, including
  missing body samples, stale timestamps, invalid body flags and mismatched
  reference streams. Legacy wrist fixtures remain explicitly labeled legacy.

These are synthetic fixtures, not measurements of the operator. Dynamic walking,
large torso shifts, actual Quest skeleton quality, thermal/FPS impact and cup/T
success remain unvalidated. Historical 72 FPS and legacy wrist-IK stress tests
must not be reported as measurements of this GMR build.

## Recording and reproduction

Y writes raw headset/controllers (`input.csv`), all 14 selected body and bind
poses plus source flags/time (`body.csv`), physical states (`frames.csv`), accepted
whole-body commands (`mimic.csv`) and events. Completion markers and source hashes
identify the episode and implementation. Record **before pressing A**, so replay
has the calibration. Inputs may contain estimated lower-body joints; confidence
is not an accuracy measurement. Recordings stay private and are excluded from Git.

After exporting an episode, use `scripts/inspect_recording.py`, then
`android/build/replay_gmr android/assets <episode-directory>` with the desktop
MuJoCo/ONNX library paths set as in `check_gmr_mac.sh`. Replay repeats retargeting
and transition blending using recorded physical calibration states; it is not a
fresh closed-loop policy rollout. The old `replay-human` refuses GMR episodes.

## Hardware acceptance still required

Install with `./android/install_quest.sh` after `adb devices` reports `device`.
Confirm `Full body tracker create: 0`, body validity and A-calibration in logcat.
Record left/right arm directions, wrist rotation, crouch, turn and small steps;
compare the raw body, retargeted reference and achieved robot state separately.
Use these recordings to determine whether remaining error comes from Meta body
estimation, source mapping, the GMR objective or TWIST2 dynamic tracking.
